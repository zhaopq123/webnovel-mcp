# 创作提示词按需取用

这个 skill 不写规则，只负责**取规则**。权威原文在 MCP 的
`prompt/CREATIVE-PROMPT.md`（sha 锁定），通过 `webnovel_craft` 按阶段/按节切片返回。
规则只有一份，别在上下文里另抄一份。

## 前提

客户端已连上 `webnovel` MCP 连接器（配置模板见仓库 `prompt/agents-md-snippet.md`）。
工具不存在时：直说没有规则库，改用 `prompt/paste-any-agent.md` 的纯文本形态。

## 五个 action

| action | 用途 | 典型调用 |
|---|---|---|
| `sections` | 列出 19 节 + 92 切片的目录与字数 | `webnovel_craft action=sections` |
| `get` | 取某一节/子节原文 | `action=get id=15.5` |
| `brief` | 按阶段装配一组切片（有预算，超了会点名） | `action=brief stage=stage6` |
| `map` | 【设定记录】20 表 → 数据模型落点 | `action=map` |
| `check` | 原文哈希/catalog 新鲜度/切片可达自检 | `action=check` |

## 阶段包

| stage | 何时用 |
|---|---|
| `negotiate` | 开工协商、开场四问、合规红线 |
| `stage1` | 核心设定（体量换算、视角、主角档案） |
| `stage2` | 世界观与层级体系 |
| `stage3` | 人物建档（三维/语言指纹/信息差） |
| `stage4` | 全书路线图 + 当前部三幕大纲 |
| `stage5` | 章纲（每批 10 章） |
| `stage6` | 正文写作（两遍交付制、去 AI 味） |
| `stage7` | 完本修订 |
| `report` | 每 10 章的连载状态报告 |
| `record` | 【设定记录】格式 |
| `protocol` | 流程总控与交互协议 |

中文别名同样可用：`正文` / `章纲` / `部纲` / `人物` / `世界观` / `报告` / `设定记录`……

## 按任务取

- **开新书**：`negotiate` → `stage1` → `stage2` → `stage3` → `stage4`。
- **拆卷/定章纲**：`stage4` + `stage5`；章纲八行格式在 `14`。
- **写正文**：`stage6`；动笔前另取 `id=15.8`（两遍交付制）、`id=15.5`（去 AI 味）、
  `id=3.6`（逻辑自检）。任务书已自动装配时直接用，不要重复取。
- **审稿**：`id=3.6`（归属核对等八问）、`id=15.5`（AI 味）、`id=15.8`（交付纪律）。
- **部收尾**：`id=2.5`（部摘要 ≤15 行）、`id=2.6`（跨部钩子）、`id=13.2`（当前部三幕）。
- **写报告**：`id=17` + `id=9.1`，或直接 `brief stage=report`。
- **落数据**：`action=map` 查【设定记录】每张表该进哪个字段。

## 纪律

1. **先取再答**：被问「规则是什么」时，用工具取原文引用，不凭记忆复述。
2. **按需取**：不要把 19 节全文一次性灌进上下文；`brief` 有预算，装不下会明确点名缺哪节。
3. **原文优先**：工具实现与原文冲突时以原文为准；`check` 报红先修规则库，别绕过去。
4. **不转述成新规则**：可以摘要帮助理解，但执行口径以切片原文为准。
