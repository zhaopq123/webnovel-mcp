# 工具书台账与一致性映射

## 1. 台账语义映射（WritingMaster 脚本台账 ↔ 非虚构概念）

| 台账文件 | 工具书概念 | 维护时机 |
|---|---|---|
| names.tsv（专名表） | 术语表（主名/别名/首现章）+口径表 | 新术语确立即录 |
| characters.json | 案例人物/机构档案（案例一致性：同一案例人物两章细节一致） | 引用案例后 |
| timeline.json | 版本与时间基准（数据年份、产品版本、政策时效——全书事实的"时间坐标"） | 涉及时效性事实时 |
| foreshadow.json | 悬置承诺（"将在第X章详述"的前向引用+交叉引用清单） | 每章交付后 |
| suspense.json | 读者问题清单（每章抛出的问题+在哪章解答——防"挖坑不填"） | 每章交付后 |
| info-gap.json | 读者已知/未知标注（前置知识依赖：本章假设读者已知什么，来自哪章） | 每章交付后 |
| plotlines.json | 论证线依赖图（论点-论据-案例的归属章，防重复展开） | 大纲期+每章 |
| summaries/ | 每章摘要（一句话功能+要点+数据点）+分部摘要 | 每章/每部末 |
| archive/ | 已定稿部分归档（历史区，引用只依据摘要） | 分部定稿后 |

## 2. 维护节奏

- 每章交付后立即 `wm-commit.sh` 提交摘要与台账增量（术语/数据点/交叉引用）。
- 每部分定稿 `wm-archive.sh` 归档；此后修改该部分=新修订轮，须重跑核查清单。
- 新会话开工前 `wm-restore.sh` 恢复；疑似异常先 `wm-doctor.sh` 体检（重点：名词表交叉引用与悬空前向引用）。

## 3. 一致性三不

不凭空回忆已写内容（查台账）；不无声引入新术语（先入表）；不留下无主的"待确认"（每条待确认必须归属某一章并在交付说明中汇总）。
