## 一、使用规则

任何命令输出 FAIL / WARN / 红 / 黄 / 打回 / 拒绝时：先在本表定位含义→按"下一步"处理→处理后重跑原命令确认。表内未登记的问题：贴完整命令输出反馈，禁止自行猜测绕过。错误码以 scripts 当前实现为唯一真相源，新增命令的错误码须同步本表（未核对前标"待确认"）。

## 二、wm-doctor 体检码（D01-D08）

| 码 | 含义 | 典型原因 | 下一步 |
|---|---|---|---|
| D01 | state.json 合法性（缺字段/track 无效/target_words 非正整数/part<1 等） | state.json 被手工编辑损坏 | 按报错字段修 state.json；恢复不了从最近备份回滚 |
| D02 | 项目必备文件完整性缺失 | 初始化未完成或某步命令没跑 | 回溯漏跑的命令，勿手工建空文件 |
| D03 | 台账 JSON 语法非法 | 手工编辑台账引入语法错 | 定位最近一次提交的更新文件，修正后重跑 |
| D04 | 专名表与交叉引用（重名/引用未声明名词/名词指向未来章节） | 名词未在 commit names[] 声明，或专名错字 | 对照 names.tsv 核对；新名词走 commit 声明 new:true |
| D05 | 悬空伏笔（埋点章>当前进度/已回收缺 resolved_ch/回收早于埋点/待回收缺 last_seen_ch） | 伏笔字段更新遗漏 | 按报错项补 commit 修正字段 |
| D06 | 章号断档/章摘要缺失 | 跳章写作或漏交摘要 | 补齐缺失章摘要后重跑 |
| D07 | parts.json 与归档不一致 | 归档中断/手工改动 parts | 重跑 wm-archive 对应部 |
| D08 | commits.log 异常 | 提交记录损坏 | 备份后按最近一次合法提交恢复 |

## 三、wm-review 红牌（打回，修复后重审）

| 红牌 | 含义 | 下一步 |
|---|---|---|
| 黑名单 | AI味/书面腔词命中（词表以 .wm/review-blacklist.txt 为准，可追加） | 换具体动作/具体感官描写 |
| 超长句 | 超长句过多（≥4处升红） | 拆句；危机场景句长另按引擎纪律 |
| 英文字母 | 正文检测到英文（正文应为纯中文） | 改中文表述（工具书术语处理见第七节注） |
| 繁体字 | 简体正文出现繁体 | 转简体 |
| 标点 | 省略号/破折号/括号引号不规范 | 按中文标点规范修 |
| 专名对照（红） | 疑似专名笔误（近似字） | 逐字对照专名表 |
| 伏笔超期 | open 状态伏笔距末次露出>12章 | 本章露出或回收，或调整台账状态 |

## 四、wm-review 黄牌（提示不拦截）

- 引号名词不在专名表：若是新名词，提交时在 commit 的 names[] 声明 new:true。

## 五、wm-commit 拒绝（CommitError，整次提交不入账）

- 字段类型/格式：非空字符串/非负整数/枚举值不符——按报错字段修正后重新提交。
- id 格式：台账编号应为"前缀-三位数"（伏笔 F-001/悬念 S-001/信息差 G-001/情节线 P-001）；id 不存在时，新增条目请省略 id 由系统自动分配。
- 无法识别的字段：更新对象含允许清单外字段——删多余字段。
- names[] 校验：名词含制表符/换行、new 非布尔、名词锁校验失败（不在专名表——新名词必须声明 new:true）。
- 别名/人物增量：别名同样受名词锁约束。
- 章摘要：summary.chapter 必须≥1，hook_type 为字符串。

## 六、未登记问题的兜底

遇到本表没有的错误：①不当作已完成；②贴完整输出（命令+全部报错行）反馈；③禁止凭印象改台账绕过。

## 七、五赛道注

- toolbook：正文英文判据与术语表纪律（toolbook-stage3-terms，术语先登记后使用）的交互口径——**待确认**（以审稿命令实际输出为准，暂按红牌处理并在术语表内登记该术语）。
- 其余赛道：无特殊分支，按通用口径执行。
